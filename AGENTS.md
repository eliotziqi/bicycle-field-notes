# Repository instructions

- Bicycle Field Notes is a static Astro site based on Inkline. Shared layout: `src/layouts/Base.astro`; navigation and features: `src/config.ts`; global styles: `src/styles/global.css`.
- Posts live in `src/content/posts/`, validated by `src/content.config.ts`. Use `getPosts()` from `src/utils/posts.ts` so production drafts stay hidden. Pages CMS is configured in `.pages.yml`; media lives in `public/media/`.
- Gallery metadata lives in `src/content/gallery/*.json`; originals stay in `public/media/`. `src/content/gallery-categories/*.json` is the single source for CMS and site categories. Keep Posts/Media CMS configuration intact; uploads alone must never become Gallery entries. Category title renames must update referencing entries. `getGallery()` validates categories/media and generates responsive WebP sizes with Astro; do not copy originals or add an image dependency. Related posts resolve only against visible `getPosts()` results.
- Home uses only Gallery entries with `showOnHomepage`; preserve empty/single-photo states, manual controls, and no autoplay/animation. Gallery filters use OR; preserve modal focus handling, Escape/arrows, lazy thumbnails, themes, and base-aware media URLs.
- Use Node 24. Install with `npm ci`; develop with `npm run dev`; validate with `npm run build` (Astro plus Pagefind), then `node tests/wiki.test.mjs` and `npm run preview`. Run `node tests/atlas.test.mjs`, `node tests/posts.test.mjs`, and `node tests/wiki-links.test.mjs`; use the documented browser/regression checks for affected UI. Search needs a production build. There is no separate lint or test script.
- `/posts/` is the only article search/filter browser. `src/scripts/posts-browser.ts` reuses Pagefind and the same static rows; `src/utils/post-discovery.ts` defines tag/Place/Trip filtering and sorting. Use OR within each dimension and AND across dimensions/text. Preserve `q`/`tags` (`tag` handles commas), repeated `place`/`trip`, sort URL state, popstate and race protection. Publication newest-first is default; experience sorting puts undated Posts last. Use `SearchField.astro`; do not add standalone Search/Tags pages or a second index.
- Follow existing Astro/TypeScript conventions: two-space indentation, double quotes, shared components, CSS tokens, semantic HTML, and accessible labels. Keep Inkline's minimal design and test narrow layouts and both themes when possible.
- Wrap internal UI URLs in `withBase()` from `src/utils/urls.ts`. The deployed project base is `/bicycle-field-notes/`, derived from `SITE.url` or `SITE_URL`. Preserve trailing slashes on page links.
- Preserve user posts, published filenames, uploaded media, favicon, CMS settings, SEO, search, and deployment workflow. Do not invent personal details or resources. Do not add dependencies or map libraries without need and authorization.
- Atlas loads MapLibre only on its route. Shared relationships live in `src/utils/atlas-graph.ts`; preserve ordered/repeated Trip visits and explicit Post narrative references separately from derived discovery membership. Trip-derived discovery does not assert visits. Public reverse associations exclude drafts. Preserve stable IDs, selection/filter separation, manual Focus, globe clustering, attribution and base-aware URLs. Never delete owner-created CMS tests automatically. Post terrain/GPX maps remain future work.
- Before editing, read AGENTS, README, PLAN, CHANGELOG and the relevant canonical Wiki guides/decisions in `src/content/wiki/`; verify them against code. Run `git status` and fetch `origin/main`. Compare branches; do not blindly pull, overwrite local work, reset, or discard changes. Never commit, push, or deploy without explicit approval.
- Keep `PLAN.md` and `CHANGELOG.md` current for meaningful changes. Keep README public-facing and concise. Preserve the original Inkline MIT notice in `LICENSE` and the Newsreader notice in `public/newsreader-license.txt`. User-authored posts, photos, and GPX files do not automatically inherit the code license.

- Wiki Markdown in `src/content/wiki/` is canonical detailed documentation; old `docs/` files are pointers. Preserve static/no-JS reading, base-aware source-relative links, public-safe content and typed Pagefind isolation (`kind:Wiki` / `kind:Post`). Do not add Wiki to main navigation or a second search service.
- Whenever behavior, schemas, publishing workflow, architecture or UI changes, update the corresponding Wiki pages and affected decision records in the same change; add a record for significant new tradeoffs. Trivial code-only changes with no documented behavior impact need no prose update. Keep PLAN/CHANGELOG current without duplicating guides; validate internal documentation links.

- Post dates use `YYYY-MM` strings and ordered Experience `{start, end}` month ranges; never restore native nested CMS date fields or content types. Preserve manual range order, reference source repeats and draft flags. `scripts/post-metadata.mjs` maintains months after saves; run its Git-history and CMS serialization tests. RSS is removed.

- CMS saves are authoring history: never sanitize incomplete entries to pass publishing. Run `npm run validate:content`, `node tests/content-validation.test.mjs` and `node tests/publication.test.mjs`; keep collection schemas shared with Astro. Automatic month changes must validate/build before committing. See `src/content/wiki/publishing/reliability.md` for failure recovery and hosted CMS acceptance boundaries.
